# Markdown 画布规范

Clado 的核心设计铁律是：**零黑盒，纯文本即全部状态**。所有结构、层级、模板约束、语义标记与连线都明文写在标准 Markdown 文件中，不维护隐藏的私有坐标数据库。

## 文件格式：标准 `.md` 纯文本

- **标准扩展名**：统一采用标准 `.md`（原生适配 GitHub / VS Code / Obsidian 等全部文本工具链）。
- **目录扫描**：位于 `<工作区>/.clado/doc/` 下的 `.md` 文档会自动纳入画布目录；普通仓库根目录下的 `README.md` 不会误入画布目录。

## YAML 文档头（Frontmatter）

在文档最顶部使用标准 YAML Frontmatter 记录文档标题与协作约束（无 Frontmatter 的纯 Markdown 文档也完全合法，会自动取第一个 `#` 作为标题）：

```yaml
---
title: 支付履约与对账链路
id: call-chain
name: 调用链路
version: 1
purpose: 从入口契约沿类方法一路追踪到数据边界，用于开发评审与代码走查。
hard_constraints:
  - 每张卡片对应一个独立职责边界或方法
  - 跨卡连线从具体内容行或语义 Tag 出发，避免卡片末尾裸连
soft_constraints:
  - 使用语义 Tag（如 [新增]{.green} / [修改]{.amber}）标明变更
organization: 入口契约 → 应用服务 → 领域服务 → 仓储与 SQL
---
```

::: info 规则头是协作契约，不是可执行代码
`hard_constraints` 与 `soft_constraints` 用来约束人和 AI 在编辑这份画布时的口径，Clado 绝不会自动执行文档中的 SQL、命令或脚本。
:::

## 标题层级（L1–L6）与三视图映射

| Markdown 语法 | 语义含义 | 卡片视图（默认） | 脑图视图 | 文档视图 |
| --- | --- | --- | --- | --- |
| `# 标题`（L1） | 一张独立卡片 | 画布上的一张卡片节点（左上角带蓝色竖条入端口） | 一级主分支节点 | 文档大节标题 |
| `##` – `######`（L2–L6） | 卡内内容小节（包含关系） | 卡片内部层级分节，可作 `#小节` 入线落点 | 逐层向右展开的思维子树 | 对应各级子标题与大纲 |
| 正文 / 列表 / 代码 / 表格 / Mermaid | 节点内容块 | 富文本渲染，支持语义 Tag 与点击进入 Lens 放大视图 | 挂在对应脑图节点内 | 完整文章流 |

::: tip 层级与连线的分工
- **包含关系**（模块 → 子功能 / 测试类 → 测试点）用 **L1–L6 标题层级** 表达，在脑图视图中天然成树。
- **调用 / 流转 / 依赖关系**（卡片 A → 卡片 B）用 **Markdown 链接** 表达，在卡片视图中自动排布为自左向右的调用链。
:::
